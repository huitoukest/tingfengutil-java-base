## 背景与目标

### 1.1 需求背景

现有 `BeanUtils.java`（663 行）经过多次迭代，存在以下核心问题：

| 问题类型 | 具体表现 |
|---------|---------|
| **职责膨胀** | 一个类包含 copyProperties、toMap、getBeanByMap、createBeanConverter 等多种功能，违反单一职责原则 |
| **缓存混乱** | 三套独立缓存（BEAN_COPY_METHOD_CACHE、BEAN_COPY_FUN_CACHE、BEAN_COPY_Field_CACHE）各自管理，key 设计不统一，容量控制不一致 |
| **API 不一致** | copyProperties 重载方法参数风格混杂（String.../Collection<String>），predicate/map 泛型不一致 |
| **性能隐患** | getBeanCopyFunMap 每次调用创建新的匿名内部类对象，未复用已解析的 BeanCopyFun |
| **模式僵硬** | 严格/非严格模式需要用户手动选择，API 复杂 |

### 1.2 重构目标（参考 Hutool 5 风格）

本次重构参考 Hutool 5 的 BeanUtil 设计风格，达成以下目标：

1. **统一门面**：提供顶层 `BeanUtil` 门面类，包含最常用的静态方法
2. **配置驱动**：通过 `CopyOptions` 配置忽略 null、字段映射、自定义转换器等
3. **自动检测**：内部自动检测使用 PropertyDescriptor（严格）或 Field 反射（非严格），用户无感知
4. **全局转换器注册表**：`ConverterRegistry` 支持注册自定义类型转换器
5. **灵活拷贝**：支持从 Map 或任意 `ValueProvider` 源拷贝到 Bean
6. **缓存优化**：使用 `SimpleCacheHelper` 缓存 BeanDesc，软引用或并发映射防止 OOM

## 功能范围

### 2.1 现有需要重构的 API

| 方法 | 问题 | 重构方向 |
|------|------|---------|
| `copyProperties(Object, Object, String...)` | 重载过多，参数风格不一致 | 统一到 BeanUtil.copyProperties + CopyOptions |
| `copyProperties(Object, Object, boolean, Collection<String>)` | 严格/非严格模式混杂 | 内部自动检测，用户无感知 |
| `copyProperties(Object, Object, Predicate, Function, String...)` | predicate 泛型不一致，API 复杂 | 通过 CopyOptions 配置化 |
| `getBeanCopyMethodMap` / `getBeanCopyFunMap` | 缓存混乱，性能隐患 | 统一到 BeanCopier 内部缓存 |
| `toMap(T, PropertyFunction...)` | PropertyFunction 繁琐 | 简化为 BeanUtil.toMap(obj, ignoreFields...) |
| `getBeanByMap(T, Map)` | a.b.c 嵌套粗糙 | 增强为 ValueProvider 机制 |
| `createBeanConverter(...)` | 与 Converter 耦合不充分 | 统一到 ConverterRegistry |

### 2.2 需要新增的功能

| 功能 | 描述 | 优先级 |
|------|------|--------|
| **BeanUtil** | 顶层门面类，静态方法入口 | Must |
| **CopyOptions** | 拷贝配置选项（忽略 null、字段映射、忽略属性、强制 Field 模式等） | Must |
| **BeanCopier** | 底层拷贝执行器，内部缓存 BeanDesc | Must |
| **ConverterRegistry** | 全局转换器注册表，支持自定义转换器注册 | Must |
| **ValueProvider** | 值提供者接口，支持从 Map 等多种源拷贝 | Should |
| **链式 API** | 支持 `BeanUtil.copyProperties(source, target, options -> options.ignoreNull(true))` | Should |
| **toBean** | 拷贝到新实例：`UserVo vo = BeanUtil.toBean(userDto, UserVo.class)` | Should |

## 核心场景

### 场景 1：简单对象拷贝（Same-Type Copy）

```java
// 简单拷贝
BeanUtil.copyProperties(userDto, userVo);

// 带配置拷贝
BeanUtil.copyProperties(userDto, userVo, CopyOptions.create().setIgnoreNull(true));
```

**验收标准**：
- [ ] 同类型对象拷贝结果与 source 属性值相同
- [ ] 修改 target 不影响 source（浅拷贝语义）
- [ ] 性能优于当前实现

---

### 场景 2：跨类型对象映射（Cross-Type Mapping）

```java
// 自动类型转换（Date → String 等）
UserDTO dto = BeanUtil.toBean(user, UserDTO.class);

// 字段名映射
BeanUtil.copyProperties(userDto, user, CopyOptions.create()
    .setFieldMapping(Map.of("userName", "name"))
    .setIgnoreNull(true));
```

**验收标准**：
- [ ] 自动匹配同名同类型字段
- [ ] 自动匹配同名不同类型字段（调用 ConverterRegistry）
- [ ] 支持自定义字段映射

---

### 场景 3：列表批量拷贝（List Batch Copy）

```java
// 批量转换
List<UserDTO> dtos = BeanUtil.toList(users, UserDTO.class);
```

**验收标准**：
- [ ] 批量拷贝性能优于循环调用单对象拷贝
- [ ] 结果列表与源列表顺序一致

---

### 场景 4：带条件过滤的拷贝（Conditional Copy）

```java
// 忽略特定属性 + 忽略 null 值
BeanUtil.copyProperties(source, target, CopyOptions.create()
    .setIgnoreProperties("password", "salt")
    .setIgnoreNull(true));
```

**验收标准**：
- [ ] 支持按字段名忽略（setIgnoreProperties）
- [ ] 支持忽略 null 值（setIgnoreNull）
- [ ] 规则可组合

---

### 场景 5：对象转 Map（Bean to Map）

```java
// 转换为 Map
Map<String, Object> map = BeanUtil.toMap(user);

// 忽略特定属性
Map<String, Object> map = BeanUtil.toMap(user, "password", "salt");
```

**验收标准**：
- [ ] 返回 Map<String, Object> 包含所有非 null 属性
- [ ] 支持按字段名忽略

---

### 场景 6：Map/ValueProvider 转对象（Map to Bean）

```java
// 从 Map 创建 Bean
User user = BeanUtil.toBean(map, User.class);

// 从任意 ValueProvider 创建
User user = BeanUtil.toBean(valueProvider, User.class);
```

**验收标准**：
- [ ] 支持 Map 转 Bean
- [ ] 支持自定义 ValueProvider
- [ ] 支持字段名映射

## 非功能需求

### 4.1 性能目标

| 指标 | 目标 | 说明 |
|------|------|------|
| 同类型单对象拷贝 | 不劣化于当前 | 复用缓存后应持平或提升 |
| 跨类型单对象拷贝 | 提升 20%+ | ConverterRegistry 查找优化 |
| 列表批量拷贝（100 条） | 提升 30%+ | 减少反射调用次数 |

**性能优化策略**：
1. 缓存已解析的 BeanDesc（属性描述），避免重复内省
2. 首次创建 Copier 时自动检测模式（PropertyDescriptor vs Field），结果缓存
3. 批量操作时预分配目标集合

### 4.2 向后兼容性要求

| 场景 | 要求 | 说明 |
|------|------|------|
| 保留现有 `BeanUtils` 类 | 必须 | 编译时警告而非错误 |
| 保留 `copyProperties` 方法 | 标记 @Deprecated | 提示迁移到 BeanUtil |
| 保留 `toMap` 方法 | 标记 @Deprecated | 提示迁移到 BeanUtil |
| 保留 `getBeanInfo` 方法 | 应该保留 | 低频但可能存在调用 |

**兼容策略**：BeanUtils 原方法委托新实现，原方法标记 @Deprecated 并提示迁移

### 4.3 缓存设计

| 项目 | 设计 |
|------|------|
| 缓存实现 | SimpleCacheHelper（已有） |
| 缓存 key | (sourceClass, targetClass, CopyOptions 的 hash) |
| 模式检测 | 内部自动检测，不暴露给用户，不影响缓存 key |
| 强制 Field 模式 | 通过 CopyOptions.forceFieldAccess(boolean) 选项 |

## 关键设计决策点（已确认）

### 决策点 1：职责划分 ✅

| 选项 | 选择 |
|------|------|
| **A：MapStruct 风格** | ❌ |
| **B：分层设计风格** | ❌ |
| **C：Hutool 5 风格** | ✅ |

**确认方案**：
- 顶层门面类 `BeanUtil`（静态方法入口）
- 底层 `BeanCopier`（拷贝执行器）
- `CopyOptions`（配置驱动）
- `ConverterRegistry`（全局转换器注册表）

---

### 决策点 2：缓存 key 中的 mode 参数 ✅

| 选项 | 选择 |
|------|------|
| **A：分离缓存** | ❌ |
| **B：配置注入** | ❌ |
| **C：自动检测 + forceFieldAccess 选项** | ✅ |

**确认方案**：
- 不对用户暴露 mode 参数
- 内部自动检测：所有属性能用 getter/setter → PropertyDescriptor；否则降级 Field 反射
- 提供 `CopyOptions.forceFieldAccess(boolean)` 用于极端情况
- 缓存 key = (sourceClass, targetClass, CopyOptions hash)，不含 mode

---

### 决策点 3：API 风格 ✅

| 选项 | 选择 |
|------|------|
| **A：链式 + 静态并存** | ✅ |
| B：仅链式 | ❌ |
| C：仅静态 | ❌ |

**确认方案**：
```java
// 静态方法风格
BeanUtil.copyProperties(source, target);
BeanUtil.copyProperties(source, target, CopyOptions.create().setIgnoreNull(true));
UserDTO dto = BeanUtil.toBean(source, UserDTO.class);

// 链式风格（通过 CopyOptions）
CopyOptions.create()
    .setIgnoreNull(true)
    .setFieldMapping(...)
    .copyTo(target);
```

---

### 决策点 4：Converter 集成 ✅

| 选项 | 选择 |
|------|------|
| **A：仅跨类型自动转换** | ✅ |
| B：所有拷贝尝试转换 | ❌ |
| C：配置控制 | ❌（但默认可配置） |

**确认方案**：
- 默认仅在跨类型时自动调用 ConverterRegistry
- 用户可通过 CopyOptions 配置是否启用自动转换
- ConverterRegistry 支持自定义转换器注册

---

### 决策点 5：向后兼容 ✅

| 选项 | 选择 |
|------|------|
| **A：标记 @Deprecated** | ✅ |
| B：直接移除 | ❌ |
| C：新包隔离 | ❌ |

**确认方案**：
- BeanUtils 保留，原方法标记 @Deprecated
- 内部委托新实现，功能一致
- 工具类只有 BeanUtils 这一个，有冲突的可以删除原有实现或方法

---

### 决策点 6：toMap 返回类型 ✅

| 选项 | 选择 |
|------|------|
| **A：Map<String, Object>** | ✅ |
| B：泛型支持 | ❌ |
| C：LinkedHashMap | ❌ |

---

### 决策点 7：target 提供方式 ✅

| 选项 | 选择 |
|------|------|
| **A：两者都支持** | ✅ |
| B：按场景分开 | ❌ |
| C：仅 target(Object) | ❌ |

**确认方案**：
- `target(Class)` → 返回新实例（如 `toBean`）
- `target(Object)` → 拷贝到已有实例（如 `copyProperties`）

---

### 决策点 8：缓存实现 ✅

| 选项 | 选择 |
|------|------|
| **A：SoftReference 包装** | ❌ |
| **B：ConcurrentHashMap** | ❌ |
| **C：SimpleCacheHelper** | ✅ |

**确认方案**：继续使用已有的 SimpleCacheHelper

## SubStory 分解

### 分析过程

**实体-功能矩阵**：

| 功能 | BeanCopier | BeanUtil | CopyOptions | ConverterRegistry | ValueProvider |
|------|------------|----------|-------------|-------------------|---------------|
| 同类型拷贝 | ✅ | ✅ | ✅ | - | - |
| 跨类型映射 | ✅ | ✅ | ✅ | ✅ | - |
| 列表批量 | - | ✅ | - | - | - |
| toMap | - | ✅ | ✅ | - | - |
| toBean | - | ✅ | ✅ | ✅ | ✅ |
| 配置驱动 | - | - | ✅ | - | - |
| 转换器注册 | - | - | - | ✅ | - |
| ValueProvider | - | - | - | - | ✅ |

**聚类结果**：
- BeanCopier + CopyOptions → 底层拷贝能力（SubStory 01）
- ConverterRegistry → 类型转换体系（SubStory 02）
- BeanUtil + ValueProvider → 上层门面 API（SubStory 03）

[DECISIONS]
- SubStory 分解:
  01 BeanCopier底层组件 | 底层拷贝执行器，BeanDesc缓存，模式自动检测，CopyOptions | 缓存复用，性能达标，支持 forceFieldAccess | 依赖: 无
  02 ConverterRegistry全局注册表 | 全局转换器注册表，支持自定义 Converter 注册和查找 | 查找优化，支持冒泡注册 | 依赖: 无
  03 BeanUtil门面层 | 顶层静态方法入口，copyProperties/toBean/toMap/toList，CopyOptions 支持 | API 一致，链式+静态并存 | 依赖: 01, 02
  04 向后兼容层 | BeanUtils原方法保留，委托新组件，标记@Deprecated | 兼容现有调用 | 依赖: 03
  05 ValueProvider支持 | 值提供者接口，支持Map等多种源到Bean的拷贝 | 增强toBean能力 | 依赖: 01
- DAG:
  01 → 03
  02 → 03
  03 → 04
  01 → 05
  03 → 05
[/DECISIONS]
