### 4.1 cache 包

#### 4.1.1 SimpleCacheHelper.evict() 修复

**问题**：第 255 行 `map.values().remove(toEvict)` 按值删除，会误删所有 equals 的成员。

**修复方案**：

```java
// 变更前（有问题）
map.values().remove(toEvict);

// 修复后 - 遍历找到对应 entry 通过 key 删除
Iterator<Map.Entry<String, SimpleCacheMember<V>>> iter = map.entrySet().iterator();
while (iter.hasNext()) {
    Map.Entry<String, SimpleCacheMember<V>> entry = iter.next();
    if (entry.getValue() == toEvict) {
        iter.remove();
        break;
    }
}
```

**边界条件**：
- `toEvict == null`：跳过删除
- `map` 为空：NOP
- 多个相同 value 的 entry：只删除第一个匹配（按引用比较）

---

#### 4.1.2 过期机制新增（新增功能）

**设计思路**：惰性删除 + 可选定期清理线程

**核心方法**：

/**
 * 带过期时间的缓存存取

 * @param value 值（允许 null）

/**

**数据结构变更**：

- `SimpleCacheMember` 保存 `expireTime`
- 内部新增 `cleanExpired()` 方法

### 4.2 collection 包

#### 4.2.1 CollectionUtils.getList() 异常处理修复

**问题**：第 48 行捕获 `FormatFlagsConversionMismatchException` 后返回 null，但其他异常被外层 catch 捕获并抛出 `BaseException`。

**修复方案**：

```java
// 变更前
try {
    return Arrays.stream(sourceString.trim().split(regex))
            .map(s -> {
                try {
                    return convert.apply(s);
                } catch (FormatFlagsConversionMismatchException e) {
                    return null;
                }
            })
            .collect(Collectors.toList());
} catch (Exception e) {
    throw new BaseException(e);  // 其他异常被抛出了
}

// 修复后 - 捕获所有运行时异常返回 null
try {
    return Arrays.stream(sourceString.trim().split(regex))
            .map(s -> {
                try {
                    return convert.apply(s);
                } catch (RuntimeException e) {
                    return null;  // 所有运行时异常都返回 null
                }
            })
            .filter(Objects::nonNull)  // 过滤掉 null
            .collect(Collectors.toList());
} catch (PatternSyntaxException e) {
    throw new IllegalArgumentException("Invalid regex: " + regex, e);
}
```

**边界条件**：
- regex 为 null/空：返回空 List（已有 guard）
- convert 抛出 NullPointerException：转换为 null 元素被 filter 过滤
- PatternSyntaxException：转换为 IllegalArgumentException 抛出

### 4.3 common 包

#### 4.3.1 ReadWriteArrayList.removeIf() 修复

**问题**：`iterator()` 返回副本迭代器，导致 `removeIf()` 操作的是副本而非底层列表。

**修复方案**：重写 `removeIf()` 方法：

```java
@Override
public boolean removeIf(Predicate<? super E> filter) {
    Objects.requireNonNull(filter);
    rwLock.writeLock().lock();
    try {
        int removeCount = 0;
        // 使用索引逆序遍历，避免 ConcurrentModificationException
        for (int i = list.size() - 1; i >= 0; i--) {
            if (filter.test(list.get(i))) {
                list.remove(i);
                removeCount++;
            }
        }
        if (removeCount > 0) {
            modCount++;
        }
        return removeCount > 0;
    } finally {
        rwLock.writeLock().unlock();
    }
}
```

#### 4.3.2 BaseTimeBufferConsumerCollection 线程池修复

**问题**：`SynchronousQueue` 无界 + 最大线程 `Integer.MAX_VALUE` 可能创建过多线程。

**修复方案**：

```java
// 变更前
private static final ExecutorService POOL_EXECUTOR = 
    new ThreadPoolExecutor(0, Integer.MAX_VALUE, 60L, TimeUnit.SECONDS, 
                           new SynchronousQueue<>());

// 修复后
private static final int CORE_POOL_SIZE = 2;
private static final int MAX_POOL_SIZE = 10;
private static final int KEEP_ALIVE_SECONDS = 60;

private static final ExecutorService POOL_EXECUTOR = 
    new ThreadPoolExecutor(CORE_POOL_SIZE, MAX_POOL_SIZE, 
                           KEEP_ALIVE_SECONDS, TimeUnit.SECONDS,
                           new LinkedBlockingQueue<>(100),  // 有界队列
                           new NamedThreadFactory("TimeBufferConsumer", true),
                           new ThreadPoolExecutor.CallerRunsPolicy());
```
