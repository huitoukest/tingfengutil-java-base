### 决策点10：ignoreCase 实现方式 → ✅ CopyOptions 配置项

用户确认：**CopyOptions.setIgnoreCase(boolean)**，属性匹配优先级（从高到低）：

| 优先级 | 条件 | 说明 |
|--------|------|------|
| 1 | 名称相同 + 类型相同 | 精确匹配，类型一致，无需转换 |
| 2 | `ignoreCase=true`: 名称忽略大小写等值 + 类型相同 | 大小写不敏感，类型一致 |
| 3 | `ignoreCase=false`(默认): 名称相同 + 类型不同 | 精确匹配，需 Converter 转换 |
| 4 | `ignoreCase=true`: 名称忽略大小写等值 + 类型不同 | 大小写不敏感 + 需转换 |

### 决策点11：ignoreError 实现方式 → ✅ CopyOptions 配置项

用户确认：**仅写到 CopyOptions**，控制「未找到适合的 Converter 时是否报错」：

| `ignoreError` 值 | 行为 |
|-------------------|------|
| `true`（默认） | 转换失败 → 静默跳过该属性，debug 日志记录（当前行为） |
| `false` | 转换失败 → 抛异常上抛 |

默认 `true` 保持与当前行为一致（向后兼容）。

### 3.2 BeanCopier — 集成 ignoreCase + ignoreError

**位置**：`bean/copier/BeanCopier.java`（MODIFY）

#### ignoreCase 匹配逻辑（核心）

在 `copy()` / `copyFromProvider()` 方法中，源端属性查找增加大小写不敏感匹配：

```text
copy(source, target, options):
  ...
  // 预构建：当 ignoreCase=true 时，构建 source 的小写→原名字典
  Map<String, String> sourceLowerNameMap = null;
  if (options.isIgnoreCase()) {
      sourceLowerNameMap = buildLowerCaseNameMap(sourceDesc.getPropertyNames());
  }

  for each propName in targetPropertyNames:
    sourceFieldName = propName
    if fieldMapping != null: sourceFieldName = fieldMapping.get(propName, propName)

    if options.isIgnoreCase():
        // 优先精确匹配（优先级1+3）
        // 精确匹配失败时降级大小写不敏感匹配（优先级2+4）
        actualSourceName = resolveSourceFieldName(sourceDesc, sourceFieldName, sourceLowerNameMap)
        if actualSourceName == null: continue  // source 无此属性
        sourceFieldName = actualSourceName

    // 取值（使用实际属性名）
    value = sourceDesc.getPropertyValue(source, sourceFieldName)

    // 然后正常类型判断逻辑...
```

**`resolveSourceFieldName` 伪代码**：

```text
resolveSourceFieldName(sourceDesc, fieldName, lowerNameMap):
  1. if sourceDesc.hasProperty(fieldName) → return fieldName（精确匹配）
  2. if lowerNameMap != null:
       ciName = lowerNameMap.get(fieldName.toLowerCase())
       if ciName != null → return ciName（大小写不敏感匹配）
  3. return null（不存在）
```

#### ignoreError 控制逻辑

修改现有 catch 块行为：

```text
// 类型转换失败时
catch (Exception e) {
    if (options.isIgnoreError()) {
        // 静默跳过（当前行为）
        debug log: "Property conversion failed: " + propName + ", skipping"
        continue;
    } else {
        // 报错上抛
        throw new BaseException("Property conversion failed: " + propName, e);
    }
}
```

**实现逻辑（伪代码）**：

```text
isEmpty(bean):
  if bean == null: return true
  desc = BeanDesc.getInstance(bean.getClass())
  for each name in desc.getPropertyNames():
    if name == "class": continue  // 跳过 Object.getClass()
    try:
      value = desc.getPropertyValue(bean, name)
      if value != null: return false
    catch BaseException: continue  // 取值失败跳过

  if bean == null: return true
  desc = BeanDesc.getInstance(bean.getClass())
  for each name in desc.getPropertyNames():
    if name == "class": continue
    try:
      value = desc.getPropertyValue(bean, name)
      if value == null: return true
    catch BaseException: continue
  return false
```

## 6. ignoreCase 属性匹配优先级详细设计

### 6.1 匹配流程

```
sourceFieldName ← 从 target 属性名经 fieldMapping 转换后得到
         │
         ▼
┌─ 名称相同 + 类型相同 ──→ 直接赋值（优先级1）
│
├─ 名称相同 + 类型不同 ──→ 走 Converter 转换后赋值（优先级3）
│
├─ ignoreCase=true + 名称大小写不敏感 + 类型相同 ──→ 直接赋值（优先级2）
│
├─ ignoreCase=true + 名称大小写不敏感 + 类型不同 ──→ 走 Converter 转换后赋值（优先级4）
│
└─ 以上均不匹配 ──→ 跳过此属性
```

### 6.2 实现细节

在 BeanCopier.copy() 中：

```text
// 步骤1：获取 source 实际属性名（处理精确匹配 + 大小写不敏感）
actualSourceName = exact match on sourceDesc
if not found AND ignoreCase:
    actualSourceName = case-insensitive match on sourceDesc
if not found: continue

// 步骤2：获取值
value = sourceDesc.getPropertyValue(source, actualSourceName)

// 步骤3：类型判断（处理优先级矩阵）
if value != null:
    targetType = getTargetPropertyType(targetDesc, propName)
    if targetType != null:
        sameType = value.getClass().equals(targetType)
        if sameType:
            // 优先级1 或 2（类型相同，直接赋值）
        else if useConverter:
            // 优先级3 或 4（类型不同，需要转换）
            try convert...
```

注意：实际 `sameType` 的判断已存在于现有代码第107行，ignoreCase 的改动仅影响步骤1中的属性名查找方式，不影响后续类型判断流程。

## 7. 核心边界条件与异常处理策略

### 7.1 新增边界条件

| 边界场景 | 处理策略 |
|----------|----------|
| `ignoreCase=true` + source 有多个属性仅大小写不同（如 "name"/"Name"） | 按 getPropertyNames() 返回顺序优先匹配先出现的那个 |
| `ignoreCase=true` + source 无匹配属性 | 静默跳过（同当前行为） |
| `ignoreError=false` + 找不到 Converter | 抛 `BaseException` 包装 `ConverterException` |
| `ignoreError=true` + 找不到 Converter | 静默跳过，debug 日志（当前行为） |
| `isEmpty(null)` | 返回 `true` |
| `hasNullField(null)` | 返回 `true` |
| Bean 无任何属性（空类） | `isEmpty()` 返回 `true`，`hasNullField()` 返回 `false` |
| Bean 只有 "class" 属性 | `isEmpty()` 返回 `true`，`hasNullField()` 返回 `false` |
| 属性获取失败（getter 抛异常） | 跳过该属性，继续遍历（静默） |

### 7.2 异常处理策略补充

| 异常来源 | ignoreError=true | ignoreError=false |
|----------|-----------------|------------------|
| Converter 转换失败 | 静默跳过该属性（debug 日志） | 同左（当前行为，catch后跳过） |
| 找不到匹配的 Converter | 静默跳过该属性（debug 日志） | 抛出 BaseException |
| 属性赋值失败 | 静默跳过该属性（debug 日志） | 抛出 BaseException |

| 场景 | 第1期行为 | 第2期行为 | 是否兼容 |
